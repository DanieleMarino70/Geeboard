05 · patterns

Screen states

Every list, chart and panel has six states designed, not three. Skeletons mirror the real layout so nothing shifts when data lands, and no state is ever a bare spinner on an empty page.

01

Waiting and arriving

A skeleton is used when the shape of the answer is known. A spinner is used only when it is not — a server starting, a world generating — and it always carries a sentence saying what is happening.

02

Nothing, broken, disconnected

An empty state always offers the two things you would have gone looking for. An error always shows the machine detail — operators paste it into support threads — but never leads with it.

empty
No snapshots yet

Take one now, or set a schedule and forget about it.

error
Daemon unreachable

fra-node-02 stopped answering 41 seconds ago. Your server is probably still running — the panel just can't see it.

ECONNREFUSED 10.24.8.2:8080
offline
You are offline

The panel is showing the last state it received, 2 minutes ago. Actions are disabled until the connection returns.

03

Confirmation and feedback

Destructive dialogs ask you to type the name — not because it stops mistakes entirely, but because it makes the object of the sentence unambiguous. Toasts never carry the only copy of an important message.
